# Knappfördröjning i SNES-emulatorer

1. Läs aktuell Snes9x-konfiguration i `~/.var/app/com.snes9x.Snes9x/config/snes9x/snes9x.conf` (`VSync`, `ReduceInputLag`). I GTK-gränssnittet heter VSync **Sync to vertical blank**; avmarkera och klicka Apply/OK för att testa utan omstart. Återställ om det inte hjälper. Jämför även gång och hopp; ett segt hopp isolerat bevisar inte allmän inputlagg. Bedöm PAL vid 50 Hz kontra 60 Hz separat som ett test av bildflyt.
2. För en jämförelse utan att ändra Media Hub: kontrollera installerade emulatorer med `flatpak list --app`. Vid behov installera bsnes med `flatpak install --user flathub dev.bsnes.bsnes`. Skapa en testkatalog med `mktemp -d "$TMPDIR/bsnes-test.XXXXXX"`. Kopiera exakt samma ROM och, om banan kräver det, den befintliga `.srm`-filen med samma basnamn. Dela inte den aktiva sparfilen mellan emulatorerna; de kan skriva över varandras framsteg. Avsluta inte ett pågående spel utan godkännande.
3. Starta bsnes i den aktiva skrivbordssessionen med `flatpak run --filesystem="$testdir" dev.bsnes.bsnes "$testrom"`, där `testrom` är den absoluta sökvägen till kopian. På den här X11-sessionen kan `DISPLAY=:0` och `XAUTHORITY="$HOME/.Xauthority"` behövas från terminalen. Kontrollera `wmctrl -lx` för ROM-titeln och använd vid behov `wmctrl -ia <id>`; läs tillbaka `_NET_ACTIVE_WINDOW` med `xprop -root`. I `~/.var/app/dev.bsnes.bsnes/config/bsnes/settings.bml` ska `RunAhead` → `Frames` vara `0` för grundtestet.
4. Kontrollera handkontrollens mappning före jämförelsen; ett verifierat spelfönster visar inte att knapparna eller den kopierade sparfilen fungerar. Låt användaren bedöma responsen i samma situation och säg vad som faktiskt är verifierat. Samma känsla med samma ROM i två emulatorer talar emot att problemet bara finns i den ena, men bevisar inte att det är en SNES-egenskap. Super Mario Bros. i Super Mario All-Stars är en ny SNES-version, inte samma ROM som NES-originalet; använd inte jämförelsen för att isolera emulatorns fördröjning.
